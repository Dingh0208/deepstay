# deepstay 上下文压缩：官方依据与实现边界

核验日期：2026-11-18（Asia/Shanghai）。通过用户指定的 AnySearch `extract` 读取以下 DeepSeek 官方原文，不含用户记录或真实 API Key。

1. [Context Caching](https://api-docs.deepseek.com/guides/kv_cache)
   - 官方说明磁盘上下文缓存默认开启，后续请求完全复用已持久化的前缀单元时可能命中缓存。
   - 官方说明缓存是 best-effort，不保证每次命中，闲置后会清除。
   - 因此缓存可以减少重复输入计算的费用，但不等于应用端的长期记忆、内容摘要或扩大模型上下文窗口。
2. [Multi-round Conversation](https://api-docs.deepseek.com/guides/multi_round_chat)
   - 官方明确 `/chat/completions` 无状态；调用方需在每次请求携带所需历史上下文。
   - 该说明展示传回历史的方法，没有描述官方 App 的自动摘要算法。

在本次读取的官方文档中没有找到官方 App 自动摘要策略的公开说明；这不代表断言所有官方渠道都没有发布过相关信息。deepstay 的“固定记忆 + 较早记录摘要 + 最近完整轮次”是本产品自己的实现，不能标注为官方 App 同款算法。

实现保留本机原始会话及分支，只替换发送给模型的历史快照。用户默认不开启压缩，设置文案说明摘要调用会计费、摘要可能遗漏细节。开启后以保守字符估计触发约 24k tokens 的阈值，近期完整轮次目标约 12k tokens，摘要单批约 6k tokens，最多 16 批，每批最多 2048 输出 tokens；字符估算不等同于上游计费 tokenizer。超出预算时明确失败，避免静默截断或自动发送昂贵的完整上下文。

缓存按供应商地址、协议、模型、消息 ID 与正文/附件元数据的 SHA-256 指纹验证；修改已摘要历史、切换分支或服务时重新检查。合成回归检验了请求规模、缓存、分支变化、完整原文保留、失败、取消、超长消息分片、续写与提醒快照预算。未使用付费真实模型请求，因此不能据此承诺特定模型的情感记忆质量或无损摘要。

## 长期陪伴场景的研究参考与取舍

同日使用 AnySearch 学术检索发现并 extract 核验了以下论文摘要：

- [RGMem: Renormalization Group-inspired Memory Evolution for Language Agents](https://arxiv.org/abs/2510.16392)：区分变化较快的对话证据和稳定偏好，按层级归纳。借鉴点是分别保留事件、偏好、更正来源；当前项目没有复现其完整框架。
- [HiMem: Hierarchical Long-Term Memory for LLM Long-Horizon Agents](https://arxiv.org/abs/2601.06377)：将具体事件与稳定知识分层并处理冲突。借鉴点是记忆栏目中保留事件时间、角色来源和更正，不把单次情绪直接归纳成稳定人格。

本版采用“每会话固定记忆 + 分批滚动摘要 + 最近完整轮次”，既能本机运行，也不需要额外向量服务。固定记忆由用户明确配置，摘要优先保留称呼、关系边界、共同事件、承诺及用户更正。会话间不共享固定记忆或摘要，通用设置的压缩开关只决定各会话是否使用自己的记忆。没有引入跨会话人物画像或自动推断用户性格。

长历史完全汇总仍有细节丢失的可能。分层原文检索是可进一步评估的方向，本版没有实现向量检索，也不宣称等同于论文系统。回归使用合成摘要与对话，验证记忆内容传递和缓存正确性；真实模型的语义召回需要用户在本地 API 配置下测试。
