## Hermes 借鉴方案：会话内记忆实现

状态：阶段一、二已实现，`pnpm type`、`pnpm lint`（136 个文件、0 warnings / 0 errors）、`pnpm test`（18 组回归）及 `git diff --check` 通过。下述功能测试均使用合成数据和模拟响应。

- 仅使用当前会话、当前分支的原文和派生记录。逐字引用通过后保存消息 ID、正文指纹与范围；更正以新记录引用旧记录，另一分支不受影响。隐藏思考、拒绝、模板及仍在流式输出/错误回答不作为记忆证据；已停止回答的可见正文可以作为来源。
- 开启压缩后按完整请求长度判断是否整理；短会话不新增模型调用。长会话保留有界最近完整轮次，最多取 6 个、约 3k 估算 tokens 的原文窗口，并使用带来源的有限核心记录和分段脉络。总输入以约 24k 的保守估算控制，必要内容超限中止。
- 每次发送最多抽取最早和最近的 2 个待处理分段，每段正文约 6k 估算 tokens，模型输出上限 4096 tokens。每段校验后单独提交，后续复用；未覆盖的历史仍可直接检索，但不启用可能过期的自动核心记忆。进度只指本轮计划的段数。
- IndexedDB v13 新增 `memoryRecords`、`memorySegments`、`memoryState`，不改原消息格式。原文与派生版本作原子比较，拒绝过期结果；删除、清空同步清理派生数据。旧 `fixed`、原始分支和附件保留，旧 `cache` 不再是新路径的记忆来源。
- 新回归入口为 `deepstay-memory-records-regression.mjs`、`deepstay-memory-recall-regression.mjs`、`deepstay-memory-storage-regression.mjs` 和更新后的 `deepstay-context-memory-regression.mjs`。重点覆盖来源校验、分支更正、增量复用、取消、存储版本竞争、会话隔离、完整请求预算及超过 16 批的长历史续聊。
- 官方流程基础上的串行新增导入、进度条和失败回滚保持原行为。本轮分别检查 80MiB 归档导入与 80MiB 单条正文的记忆管线；即使管线测试通过，也不能据此证明整条 `session` 的读取、克隆、保存和 JSON 解析已实现低内存。消息分页及增量 JSON 解析属于尚未实施的阶段三。

本轮主链回归共 14 项，使用 35 次模拟抽取，包含 80MiB 单条正文中部日期召回、超过 16 批历史仅作两次有界抽取、拥挤账本中的相关更正、用户更正助手角色设定/承诺、来源编辑失效、分支隔离、停止后已提交段复用及真实 DeepSeek 续写的正文/思考签名/提醒/模型保留。召回相关度相同时优先保留较新的原文，避免重复的旧提法挤出新表达；独立召回回归验证该情形。存储回归覆盖升级、版本竞争、幂等、事务回滚、导入隔离与删除后拒绝迟到写入。

实际 Web 使用 `localhost:8090` 开发服务和独立模拟 origin `http://127.0.0.1:18119`，未读取或修改用户 Key。通过界面导入长短两个会话，共 202 条原始消息；100 轮长会话包含早期“星光海岸／周五看海”，短会话使用“队长／周日观星”。长会话首轮两次结构化抽取后进入主聊天，实际请求仅 7 条消息并包含早期原文证据；第二轮保留旧段、只补两个新段。原始 200 条逐项保留，新增两轮后共 204 条。短会话发送零抽取且无另一个会话的记忆。1280px、390px、320px 下压缩设置保持单行、无记忆入口和说明、无横向溢出、背景无设置预览；本轮整理进度与停止按钮可见。截图及证据保存在本机 `memory-web-20261118` 目录，预览保留供用户测试。
