# 关闭自动上下文压缩的修复验收

日期：2026-11-23。工作版本：0.1.19；本次尚未打包或发布。

## 问题与原因

关闭自动压缩时，旧逻辑虽然不请求新的摘要，仍会按输入预算裁短历史；接口超限后也会裁短重试。存在已保存的压缩检查点时，复用过程还会移动近期原文起点。用户因此可能感觉每轮都在整理；上下文预估同样显示了裁短后的结果。另一个问题是关闭开关不会立即取消已经开始的自动整理。

## 修复后的行为

- 关闭自动压缩后，发送、重新生成和官方接口续写均不自动整理，不按预算裁短历史，也不在超限后缩短重试。
- 已成功保存的压缩结果继续复用，但保留检查点的原文起点；缩小窗口也不继续缩短历史。
- 超限时只提交一次，提示手动压缩、调整窗口或切换模型；不删除本地历史。
- 关闭开关会立即中止在途自动整理，清除整理进度；不打断已经进入普通生成的回复。
- `/compact` 与手动压缩按钮仍可使用，自动开关保持关闭。
- 上下文预估按相同开关行为计算，关闭时不显示暗中裁短后的结果。

本次不调整开启自动压缩时的触发阈值或增长轮数门槛。

## 验证结果

先增加回归复现关闭时最早历史被裁掉，再修复实现。新增 `tests/deepstay-compaction-optout-regression.mjs` 使用真实聊天状态、请求序列化、SSE 与 IndexedDB，配合合成历史和模拟接口验证：

- OpenAI-compatible、Anthropic-compatible、官方 DeepSeek 三种协议；连续短消息、重新生成，以及官方续写。
- 无自动抽取、无新记忆写入，最早历史保留；关闭时的估算允许反映真实超限。
- 手动整理后固定检查点复用；接口超限只请求一次并提供明确提示。
- 关闭开关取消在途抽取，下一次可正常发送；冷重载后开关仍关闭；普通生成不被误停。

类型检查与 lint 通过。两轮完整 `pnpm test` 各通过 53 套回归，覆盖既有 80 MiB 记忆和预估、来源一致性及取消事务测试。两轮日志分别保存在：
