# 人物预设与角色卡

侧栏「人物预设」、空白新对话的「选择人物预设」，以及「设置 → 聊天与 AI → 人物预设」均可打开人物库。可以新建、编辑、删除、导入角色卡、导出单个人物，或选择「开始对话」。名称和人物设定必填，开场白可留空。

## 会话隔离

人物库保存可重复使用的模板。开始对话时将名称、设定和开场白复制到新会话的 `character` 快照；普通新对话和既有历史不会自动绑定人物。修改、删除库中的预设，只影响之后新建的对话，已创建的聊天和人物快照保留。同一个人物开启的不同会话也分别保存历史和会话内记忆，没有跨会话记忆。

开场白作为一条独立助手消息显示，不会为它请求模型，也不会伪造用户提问。它没有对应问题，不能重新生成或续写。后续请求将人物设定和已显示的开场语境加入系统信息，兼容要求首轮为用户消息的接口。

删除开场消息时，也会移除当前会话后续请求中的开场语境；人物设定、人物库和其他会话的开场白保留。

## 提示与上下文预算

实际聊天使用「全局系统设定（未填写时使用应用默认）＋当前会话人物设定＋开场语境」，之后按现有逻辑加入当前分支的记忆。人物不依赖自动压缩开关；首次发送、重新生成、续写和复用压缩结果时都使用会话快照。

人物文本计入请求、输入区估算和手动／自动压缩的系统开销预算，裁剪历史时保留。压缩处理当前会话的聊天记录，不会重写人物库或会话人物设定。设置过长仍可能占用模型窗口；本机字符限制不等于服务商 Token 数，角色卡导入成功也不代表任意模型都能容纳其全部文本。

上下文详情标注「下一次请求估算」，复用当前分支已有的压缩结果，并反映草稿、人物设定及附件引用；最近一轮实际用量另列。生成中显示待结算，估算不调用模型、不解析附件，也不能推算服务端文档解析后的精确 Token。

## 角色卡支持范围

| 文件 | 当前读取方式 |
| --- | --- |
| deepstay JSON | `format: "deepstay-character"`、`version: 1`，读取 `name`、`prompt`、`greeting`。 |
| V1 JSON | 读取顶层人物字段。 |
| V2 / V3 JSON | 识别 `chara_card_v2` / `chara_card_v3`，读取 `data` 中的文字字段。 |
| PNG 角色卡 | 读取 `tEXt` 中的 `ccv3` 或 `chara` Base64 JSON；两者同时存在时优先 `ccv3`。不把图片保存为人物头像。 |
| CHARX | 读取 ZIP 根目录的 `card.json`，跳过其他资源。 |

外部卡将 `system_prompt`、`description`、`personality`、`scenario`、`mes_example` 和 `post_history_instructions` 合并为一份人物设定。开场白优先采用 `first_mes`，缺少时选择第一个非空 `alternate_greetings`，不会导入全部候选开场。

`{{char}}` 替换为昵称（没有昵称时使用名称），`{{user}}` 固定替换为「用户」。世界书、脚本、外部资源和其他宏不会执行；不提供完整 SillyTavern 提示词排布、动态变量、世界书召回或插件兼容。`post_history_instructions` 在这里作为人物文字保存，不具有原应用的独立插入位置。

选择角色卡后先进入可编辑表单，确认保存才写入人物库；取消不新增人物。导入只在本机解析，不上传角色卡或读取外部资源。开始聊天后，系统设定和对话按所选接口正常发送给模型服务。

单文件上限 20 MiB，JSON 正文（包括 PNG / CHARX 内提取内容）上限 200 KiB；名称不超过 100、人物设定不超过 20,000、开场白不超过 10,000 个 JavaScript 字符。名称和人物设定不能全为空白，超限或格式错误会拒绝导入，不静默截断。导出为 deepstay JSON，仅包含上述三个文字字段，不导出 PNG、CHARX 或原卡的完整元数据。

## 本机保存与备份

人物库独立保存在现有 IndexedDB 的 `characterPresets` 表，会话快照随会话保存。删除人物不级联删除聊天；清空聊天历史也不删除人物库。

历史 v3 ZIP 通过可选的 `deepstay_character` 保存会话人物快照，包含 `presetId`、`name`、`prompt` 与可选 `greeting`。旧 DeepSeek 归档没有该字段时行为不变。新导入会话带入快照；相同来源的增量导入保留本地快照，包括保留旧会话「未配置人物」的状态，不用外部卡覆盖它。字段错误会使本次导入失败，原有历史保留。

历史 ZIP 不包含人物预设库，也不会向库中添加角色。要备份可重复使用的人物模板，请逐个导出 JSON；会话快照可通过历史 ZIP 备份。浏览器和 Android 的人物库互不共享，没有云同步。

## 实现位置

- `src/services/characters.ts`：人物库操作、快照与系统提示组合。
- `src/services/characterCards.ts`：本机角色卡读取及文字映射。
- `src/components/characters/`：人物库与编辑界面。
- `src/services/chat/store.ts`：新建人物对话、发送与压缩预算。
- `src/services/chat/history/`：会话人物快照的 ZIP 往返兼容。

功能参考 DSH Go 的酒馆角色卡入口，按 DeepStay 直接调用模型及本机会话架构独立实现，没有复制酒馆引擎或品牌素材。实现差异见 [DSH Go 对照](DSH_GO_COMPARISON.md)；测试及发布状态以本版实际验收记录为准。
