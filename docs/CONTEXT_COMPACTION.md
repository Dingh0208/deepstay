# 压缩触发、预算和记忆保留

0.1.14 起，自定义上下文容量按接口协议、规范化请求地址和模型分别保存；同名模型处于不同接口时互不影响。旧版全局容量只迁移到原来选中的路由。设置、聊天窗口分母、请求预算和自动压缩读取同一份当前路由容量；其他生成参数与全局设定仍保持全局。

0.1.15 起，底部展示「下一次请求估算」，按当前分支、文字草稿、人物设定、工具、附件引用与已保存的压缩结果计算，并采用本次运行中接口已确认的更小输入预算。最近一轮服务端实际用量单独列出。估算防抖、可取消，不请求模型、不上传或解析附件、不改写记忆；服务端文档内容和实际 tokenizer 不可在本机精确预测。大历史估算只读派生记忆，不重读整份会话，也不为预览重新哈希原文；实际发送仍完整校验来源。

DeepStay 默认关闭自动上下文压缩。在聊天底部打开「上下文窗口」并选择手动压缩，或单独发送 `/compact`，都可以整理当前分支。手动整理用同一个停止按钮，不创建问题或回复。关闭自动压缩后，后续发送仍会复用当前分支已成功保存的压缩结果。

未自定义时，上下文窗口按 1,000,000 tokens 计算；请求预算、自动整理和手动整理都使用当前路由的窗口或该路由已确认的更小输入上限。自动整理参考 DSH Go：估算输入达到 `min(窗口的 80%, 窗口 - 输出预留 - 安全余量)` 时准备整理；输出预留优先采用用户设置的最大输出量，未设置时最高按 8,192 tokens 估算，安全余量最高为 65,536 tokens。成功后保存近期原文的起点和当时最后一轮的标记，约保留可用窗口的 16% 作为完整近期轮次；此后至少有四个新的完整轮次并再次接近阈值，才发起下一次自动整理。手动整理短会话时按当前历史大小缩小保留目标，不会因为 1M 窗口而对中短对话无操作。

整理请求使用当前选中的接口地址、协议、密钥和模型，覆盖官方 DeepSeek、OpenAI-compatible 与 Anthropic-compatible 路由。最多约 6,000 估算 tokens 的预算包含整理提示、已核验记录、原文标记和有界来源样本；请求组装后再次核算，并为模型输出与误差留出空间，再按当前路由的上下文窗口下调。第三方路由不发送 DeepSeek 专用的 `safety_check` 字段。服务端报告更小上下文上限时，抽取重试按该上限重算提示词和输出额度，并将保守后的输入上限绑定到当前接口、模型和密钥，供本次后续聊天、预测及后续请求共用；如果服务端只报超限而未给出数字，最多再逐步缩小提示词、输出额度和来源样本两次。其他截断或无效结果只缩小来源样本重试一次。只有完整且通过原文引用验证的结果会写入本地。辅助请求最长等待 180 秒，用户取消立即生效。连接失败、上下文限制、预算不足、服务端拒绝、超时、无效/截断输出与本地保存冲突使用不同提示。整理失败或自动重试冷却期间，不会把裁短后的历史当成完整上下文发送；原始会话保留，用户可手动再整理或稍后重试。

模型收到开场用户原话节选、近期完整轮次、已核验的会话记忆与相关原文。整理提示优先保留称呼、自称、人物和关系设定、互动边界、情绪脉络、约定和更正。已整理的片段不重复提交；极长记录仍按有界样本逐步覆盖，缺少覆盖时不会把历史记录认作最新事实。与 DSH Go 将较旧消息范围汇总为单段摘要不同，DeepStay 的记忆抽取保留来源片段引用与事实记录，避免把整段近百万 token 原文复制到一次辅助请求；所有原始消息和附件仍在本机，可继续检索。真实模型对语气和记忆的表现仍会受模型及对话内容影响。

这套设计参考 Hermes 保留开头和尾部、留出后续输入空间、区分持久记忆和会话摘要的做法。DeepStay 把原文检索和事实校验限定在当前会话的当前分支，并复用已经验证的分段而无需重写一份总摘要。参考 [Hermes 上下文压缩与缓存](https://hermesagent.org.cn/docs/developer-guide/context-compression-and-caching)、[官方压缩器源码](https://github.com/NousResearch/hermes-agent/blob/main/agent/context_compressor.py)和 [Persistent Memory](https://hermes-agent.nousresearch.com/docs/user-guide/features/memory)。
